Processing Block

Each implementation MUST describe how they implement each of the processing steps [S-1] - [S-11] in Chapter 4 with as much infomration as possible given the implementation-specific capabilities and/or limitations.

Minor variations in the inputs and outputs of each steps are acceptable SHOULD they fall within the intents of each step.

It is anticipated that not all implementations will be able to fully replicate each of the defined processing steps. An implementation MAY "short-circuit" steps when completing the implementation template. When short-circuiting one of more steps, the implementation MUST use the inputs of the first step it short circuits and return the outputs of the last step it short circuits. For example, if the implemenation does not implement step 2,3 and 4, it will specify a step 2-3-4 that has for intput the inputs of step 2 and for output the outputs of step 4.

For the purpose of clarification within the implementation template, an explanation MUST be provided as to why the steps where short circuited. Specifically, the implemenation SHOULD include all of its implicit assumptions that correspond to the behaviors and FDO building blocks specified within the short circuited steps.

Completed processing block implemenation template are targetted at the following communities:

  • FDO system developers that want to document their implementations and be able to characterize its compatibility with the FDO specifications.
  • FDO system developers that want to understand how to implement an FDO solutions for a particular set of technologies.
  • Cross FDO gateways developers that need to enable for the free flow of FDOs from one implementation to another
  • The FDO Forum for associating a standardized functional description and capability for each different FDO Implementation.
It is anticipated that these implementation templates will often be used by AI services to build the needed interoperable pathways accross any of these various implementations.
